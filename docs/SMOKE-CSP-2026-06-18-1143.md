## Violations CSP détaillées

### 1. `vercel.live/feedback.js` — `script-src` (ENFORCE, bloquant sur preview)
```
directive : script-src-elem
blocked-uri: https://vercel.live/_next-live/feedback/feedback.js
disposition: enforce
console    : "Loading the script 'https://vercel.live/_next-live/feedback/feedback.js'
              violates ... directive: \"script-src 'self' 'unsafe-inline'\"."
```
- **Origine** : script injecté par la **plateforme Vercel** sur les déploiements *preview*
  (Vercel Toolbar / commentaires). Ce n'est pas une ressource de HaloCard.
- **Production** : `vercel.live` n'est **pas injecté** → cette violation **n'existera pas**
  en prod. Vérifié : sur prod, `externalResources = []` (aucun script tiers).
- **Impact** : nul sur l'app ; au pire la barre d'outils Vercel/commentaires ne se charge
  pas sur les previews.

### 2. Prefetch RSC `/login` — `connect-src` (report-only sur prod ; serait enforce en prod)
```
directive : connect-src
blocked-uri: https://halocard.ch/login?_rsc=5CB68i4pnAekjehf
disposition: report
contexte   : halocard.ch/login renvoie 308 -> https://app.halocard.ch/login (cross-origin)
             requête observée : fetch GET https://app.halocard.ch/login
```
- **Cause** : le routeur Next **prefetch** le payload RSC des liens app (`/login`, etc.)
  via `fetch`. Sur la prod, ces routes redirigent (308) de l'apex `halocard.ch` vers le
  sous-domaine `app.halocard.ch` ; `connect-src 'self' …` n'inclut **pas** `app.halocard.ch`
  → le prefetch (et son redirect cross-origin) est refusé.
- **Impact fonctionnel : AUCUN.** Le **clic** sur le lien déclenche une **navigation
  top-level** (non régie par `connect-src`), qui suit le 308 → `app.halocard.ch/login`
  s'affiche normalement (vérifié par clic réel). Seule l'**optimisation de prefetch**
  inter-sous-domaines est perdue.
- **Note** : non observé sur la preview (hôte unique `*.vercel.app`, pas de cross-origin).
  Apparaîtra en prod après merge sur les liens apex→app.

### 3. Scripts inline d'hydratation — `script-src-elem` blocked-uri `inline`
- **Report-only sur prod** (8 sur `/`, 5–6 ailleurs) car la CSP prod actuelle est
  `script-src 'self'` (sans `'unsafe-inline'`).
- **Sous l'enforce de #35** (`script-src 'self' 'unsafe-inline'`) : **AUTORISÉS** →
  **0** violation inline sur la preview enforce. C'est exactement ce que #35 corrige.

### Inventaire ressources (preuve d'absence de blocage app)
- **Scripts externes / styles externes / polices externes** : **AUCUN** sur toutes les
  pages (`externalResources = []`). Tous les scripts app sont `/_next/...` (same-origin).
- **`connect-src` réellement utilisé par l'app** : Supabase (`*.supabase.co`, whitelisté)
  + Sentry ingest (`o4511571146178560.ingest.de.sentry.io` ⊂ `*.ingest.de.sentry.io`,
  whitelisté). **Tout est couvert.**
- **CSS appliqué** (`document.styleSheets.length ≥ 1`), corps de page rendu là où la BD
  est disponible.
